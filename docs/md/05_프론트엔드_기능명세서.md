# 1. 문서 개요

## 1.1 목적

이 문서는 「여행말」 모바일 웹 프론트엔드가 제공하는 기능을 화면 단위로 정의한다. 백엔드 담당자는 화면이 요구하는 API와 상태 전이를, 디자인·QA 담당자는 화면별 동작·예외 처리·수용 기준을 이 문서로 확인한다. 발표 시연에서 “처음부터 끝까지 끊기지 않고 돌아가는 것”을 우선 기준으로 한다.

## 1.2 서비스 개요

여행 중 찍은 사진을 올리면 장면으로 묶어 주고, 밤마다 AI가 건 음성 인터뷰에 답하면 그날의 챕터가 써진다. 여행이 끝나면 챕터가 한 권의 책으로 엮이며, 문장마다 “사진과 내가 한 말”이라는 근거를 확인할 수 있다.

## 1.3 용어

| 용어 | 뜻 |
|---|---|
| 여행(Trip) | 장소·기간·동행으로 만든 하나의 여행. 한 번에 하나만 진행 중일 수 있다(진행 중 여행 = inProgressTrip). |
| 일차(Day) | 여행의 날짜 단위. 하루에 사진 올리기 → 장면 → 인터뷰 → 챕터 초안이 한 번 돈다. |
| 장면(Scene) | 시간·장소로 묶인 사진 묶음. 사진이 없는 빈 시간은 “간격 장면(질문 후보)”. |
| 인터뷰 | 장면을 근거로 AI가 묻고 사용자가 음성으로 답하는 턴제 통화. 한 판은 질문 5개. |
| 챕터 | 하루 인터뷰와 사진으로 쓴 이야기 한 편. 여행이 끝나면 챕터들이 한 권의 책이 된다. |
| 근거(Evidence) | 책의 문장을 뒷받침하는 사진·사용자의 말(전사)·저장된 음성. |
| 작업(Job) | 서버에서 오래 걸리는 처리(사진 분석, 챕터 작성, 책 엮기, 문체 변경). jobId로 상태를 확인한다. |

## 1.4 전체 화면 흐름

| 단계 | 화면 | 경로 | 다음으로 가는 조건 |
|---|---|---|---|
| 1 | 닉네임 입력 | /start | 닉네임 입력 후 「책장 만들기」 |
| 2 | 책장 | / | 「새 여행 시작하기」 또는 진행 중 책 블록 |
| 3 | 새 여행 시작하기 | /trips/new | 장소·날짜·동행 입력 후 「여행 시작」 |
| 4 | 오늘 사진 올리기 | /trips/:id/today/upload | 사진 선택 → 업로드 → 분석 완료 |
| 5 | 장면 분석 결과 | /trips/:id/today/scenes | 「인터뷰 시작하기」 |
| 6 | 인터뷰 통화 | /trips/:id/today/call | 질문 5개 완료 또는 중간 종료 → 「오늘의 챕터 만들기」 |
| 7 | 이야기를 쓰는 중 | /trips/:id/today/writing | 서버 작업 완료(2초 간격 확인) |
| 8 | 오늘의 챕터 초안 | /trips/:id/today/draft | 보통 날: 책장으로 / 마지막 날: 「여행 마치고 책 만들기」 |
| 9 | 책을 엮는 중 | /trips/:id/binding | 서버 작업 완료(2초 간격 확인) |
| 10 | 책 완성 | /books/:id/complete | 「책장에 꽂기」 또는 「지금 읽기」 |
| 11 | 책 상세 · 리더 | /books/:id, /books/:id/read | 읽기, 근거 확인, 문체 변경 |

## SC-01 처음 방문: 닉네임으로 책장 만들고 첫 여행 시작

| 목표 | 로그인 없이 닉네임만으로 시작해 첫 여행을 만든다. |
|---|---|
| 사전 조건 | 브라우저에 서버가 발급한 쿠키가 없다. |

| # | 사용자 행동 | 시스템 반응 | 화면 |
|---|---|---|---|
| 1 | 앱 주소(/)로 접속한다. | 쿠키로 확인된 사용자가 없으므로(GET /users/me가 401) /start로 이동시킨다. | S-01 빈 상태 |
| 2 | 닉네임 입력창에 “서준호”를 입력한다. | 입력창이 강조되고 “서준호님의 책장” 미리보기가 나타난다. 「책장 만들기」가 활성화된다. | S-01 입력 완료 |
| 3 | 「책장 만들기」를 누른다. | 버튼이 “책장을 만드는 중…”으로 바뀌고 POST /users를 호출한다. 성공하면 서버가 쿠키를 발급하고 /로 이동한다(뒤로 가기로 /start에 돌아오지 않음). | S-02 빈 상태 |
| 4 | 「새 여행 시작하기」를 누른다. | /trips/new로 이동. 장소·날짜·동행이 기본값으로 채워져 있다. | S-03 |
| 5 | 장소 “전주”, 날짜 2026.07.13–07.15, 동행 “친구”를 확인하고 「여행 시작」을 누른다. | POST /trips 호출. 성공하면 책장 캐시를 비우고 사진 올리기 화면으로 이동한다. | S-04 선택 전 |

### 대안 · 예외 흐름

- 닉네임을 비운 채 입력창을 벗어나면 “닉네임을 한 글자 이상 입력해 주세요”가 보이고 버튼은 계속 비활성이다.
- 서버 오류 시 “책장을 만들지 못했어요. 입력한 이름은 그대로 있어요.”가 보이고 「다시 시도」로 재요청한다.
- 날짜 시트에서 종료일을 시작일보다 앞으로 지정할 수 없다(종료일 입력이 시작일 이후만 허용).

기대 결과: 닉네임이 저장되어 책장 머리글에 “서준호님의 책장”이 보이고, 새 여행이 생성되어 첫날 사진 올리기 화면에 도착한다.

## SC-02 하루 기록: 사진 올리기 → 장면 확인 → 인터뷰 → 챕터 초안

| 목표 | 하루 동안 찍은 사진과 5개의 질문 답변으로 그날의 챕터 초안을 얻는다. |
|---|---|
| 사전 조건 | 진행 중인 여행이 있고(오늘 N일차), 인터뷰 이전 상태이다. 마이크가 있는 기기이며 HTTPS 또는 localhost로 접속했다. |

| # | 사용자 행동 | 시스템 반응 | 화면 |
|---|---|---|---|
| 1 | 사진 올리기 화면에서 「오늘 찍은 사진 고르기」를 눌러 사진 42장을 고른다. | 3열 격자로 모두 선택(체크)된 상태로 보여 주고, 「사진 42장 올리기」가 활성화된다. | S-04 선택 후 |
| 2 | 「사진 42장 올리기」를 누른다. | POST upload-urls → 받은 주소로 사진을 3장씩 동시에 직접 업로드. “사진을 올리고 있어요 · n / 42”와 진행 막대가 올라간다. | S-04 업로드 중 |
| 3 | (대기) | 전부 올라가면 POST analyze → jobId. 2초마다 상태 확인. “사진을 읽고 있어요 · n / 42”. | S-04 읽는 중 |
| 4 | (대기) | 작업 완료 → 장면 화면으로 자동 이동. | S-05 |
| 5 | 장면 카드(예: 경기전, 콩나물국밥집, 사진 없음 14:00–16:50, 골목 카페, 오목대)를 훑어본다. | 장면 타임라인을 보여 준다. 사진 없는 간격은 점선 카드(질문 후보)로 표시된다. | S-05 |
| 6 | 「인터뷰 시작하기」를 누른다. | 통화 수신 화면으로 이동. “오늘 사진 N장을 봤어요 / 이야기 들려주실래요?” | S-06 수신 |
| 7 | 「받기」를 누른다. | 오디오 재생을 잠금 해제하고 마이크 권한을 요청한다. 허용되면 POST interview/start로 첫 질문을 받는다. | S-06 |
| 8 | 질문을 듣는다. | 질문 음성이 재생되고 “AI가 말하는 중” 파형이 움직인다. 질문 말풍선과 근거 장면 카드가 보인다. | S-06 말하는 중 |
| 9 | 질문이 끝나면 말로 답한다. | 자동으로 녹음이 시작되고 “듣고 있어요”로 바뀐다. 말소리가 잡히면 파형이 움직이고, 말이 끝나고 2초 조용하면 자동으로 다음 단계로 넘어간다. | S-06 듣는 중 |
| 10 | (대기) | 녹음 파일을 POST answer로 보내는 동안 “생각하는 중”. 다음 질문이 오면 8번으로, 5번째 질문까지 끝나면 마무리로 간다. | S-06 생각하는 중 |
| 11 | 마무리 화면에서 「오늘의 챕터 만들기」를 누른다. | 통화 시간·질문 수·장면 수·오늘의 순간 칩을 보여 주고, POST chapter → jobId. 쓰는 중 화면으로 이동한다. | S-06 → S-07 |
| 12 | (대기) | 2초마다 확인. 완료되면 초안 화면으로 자동 이동. | S-07 → S-08 |
| 13 | 초안을 읽고 「책장으로 돌아가기」를 누른다. | 책장으로 이동. 진행 중 책 블록이 “오늘 완료 / 내일 밤에 다시 만나요”로 보인다. | S-02 오늘 완료 |

### 대안 · 예외 흐름

- 5번째 질문 전에 그만하고 싶으면 SC-04(끊기)를 따른다.
- 말이 길어져도 한 답변은 55초에서 자동 종료된다(6.2장).
- 질문이 마음에 들지 않으면 「이 질문 건너뛰기」로 넘어간다. 다시 듣고 싶으면 「다시 듣기」.

기대 결과: 그날의 챕터 초안(“2일차 · 비 오는 전주 / 비 오는 날의 손님” 등)과 포착 순간 칩이 보이고, 책장은 “오늘 완료” 상태가 된다.

## SC-03 사진 일부 업로드 실패 후 재시도

| 목표 | 네트워크 문제로 일부 사진만 실패해도 이미 올라간 사진을 잃지 않고 이어간다. |
|---|---|
| 사전 조건 | 42장을 선택하고 업로드를 시작했다. |

| # | 사용자 행동 | 시스템 반응 | 화면 |
|---|---|---|---|
| 1 | 「사진 42장 올리기」를 누른다. | 업로드가 진행된다. 이 중 3장이 실패한다. | S-04 업로드 중 |
| 2 | (대기) | 모든 시도가 끝난 뒤 “3장을 올리지 못했어요 / 나머지 39장은 안전하게 담겼어요”를 보여 준다. 실패한 사진은 붉게 표시된다. | S-04 일부 실패 |
| 3 | 「실패한 3장 다시 올리기」를 누른다. | 실패한 3장만 새 업로드 주소를 받아 다시 올린다. 성공하면 자동으로 분석 단계로 넘어간다. | S-04 → 읽는 중 |

### 대안 · 예외 흐름

- 「올라간 39장으로 계속하기」를 누르면 실패 사진은 제외하고 분석을 시작한다.
- 업로드 주소를 받는 단계에서 실패하면 “업로드 주소를 받지 못했어요. 이미 올라간 사진은 그대로 있어요.”와 「다시 시도」를 보여 준다.
- 분석 작업이 실패하면 “사진은 모두 저장됐어요. 장면을 묶지 못했어요.”와 「다시 시도」(분석만 다시 요청)를 보여 준다.

기대 결과: 이미 올라간 사진을 다시 올리지 않고 실패한 것만 재시도하며, 어느 단계의 실패든 “무엇이 저장되어 있는지”를 안내받는다.

## SC-04 통화 도중 끊기: 저장하고 마치기 / 계속하기 / 저장 안 함

| 목표 | 인터뷰 도중 그만두더라도 이미 답한 내용을 지키고 선택권을 준다. |
|---|---|
| 사전 조건 | 통화 중(질문 3/5에서 3번째 질문에 답하는 중). |

| # | 사용자 행동 | 시스템 반응 | 화면 |
|---|---|---|---|
| 1 | 끊기(빨간 전화) 버튼을 누른다. | 바로 끊지 않고 확인 시트를 연다. 질문 음성은 일시정지하고 진행 중이던 녹음은 버린다. | S-06 끊기 확인 |
| 2 | 시트 문구를 읽는다. | “인터뷰를 여기서 마칠까요? 지금까지 답한 질문 2개는 저장돼요. 남은 질문 3개는 건너뛰어요.” | S-06 끊기 확인 |
| 3a | 「여기까지 저장하고 마치기」를 누른다. | 마무리 화면으로 이동(질문 2개). 서버에 알려 남은 질문을 건너뜀 처리한다(SAVE_EXIT). 이어서 「오늘의 챕터 만들기」로 챕터를 만들 수 있다. | S-06 마무리 |
| 3b | 「계속 이야기하기」를 누른다. | 시트를 닫고 현재 질문(3번)을 처음부터 다시 들려준다. | S-06 말하는 중 |
| 3c | 「저장하지 않고 나가기」를 누른다. | 통화를 종료하고 책장으로 이동한다. 서버에 알려 이번 인터뷰의 음성·전사를 삭제하게 하며(DISCARD) 마무리(챕터 만들기)는 하지 않는다. | S-02 |

### 대안 · 예외 흐름

- 시트가 열려 있는 동안 직전 답변의 서버 응답이 도착하면 바로 재생하지 않고 보류한다. 시트를 닫을 때(계속) 다음 질문을 재생하고, 「저장하고 마치기」를 누르면 마무리로 간다.
- 시트 바깥(어두운 영역)을 누르면 「계속 이야기하기」와 같다.
- 답한 질문이 0개인 상태에서 마쳐도 마무리 화면은 열린다(“질문 0개”). 건너뛴 질문과 빈 답변은 “답한 질문”으로 세지 않는다.
- 이어 하기: 통화를 끊고 나갔다가 다시 「받기」를 누르면 서버가 첫 미답변 질문부터 돌려주고 이미 답한 수(answered)를 이어서 센다.

기대 결과: 사용자는 통화를 바로 끊기지 않으며, 세 가지 선택에 따라 정확히 한 가지 결과(마무리 / 재개 / 이탈)만 일어난다.

# 3. 공통 사항

## 3.1 사용자 식별 · 접근 제어

- 로그인·회원가입이 없다. /start에서 닉네임만 받으면 서버가 쿠키(HttpOnly, 서버 발급 토큰)를 발급해 사용자를 구별한다. 화면은 쿠키를 읽을 수 없으므로 GET /users/me로 로그인 상태를 확인한다.
- 쿠키로 확인된 사용자가 없으면(GET /users/me 401) 어느 경로로 들어와도 /start로 이동한다. 사용자가 확인된 상태에서 /start로 들어오면 /로 이동한다. 정의되지 않은 경로는 /로 이동한다. 어떤 요청이든 401이 오면(쿠키 만료) 다시 /start로 보낸다.
- 모든 서버 요청은 /api 접두로 같은 출처에 보내며 쿠키가 자동으로 따라간다(credentials: include). 쿠키를 잃으면 기존 책장을 복구할 수 없다.

## 3.2 화면 규격

- 기준 폭 390px. 더 넓은 화면에서는 가운데 정렬하고 최대 폭을 430px로 제한한다. 360~430px에서 가로 스크롤이 생기지 않는다.
- 모바일 전용이며 PC 레이아웃과 다크 모드 전환은 지원하지 않는다. 통화 화면의 어두운 배경은 해당 화면 고유의 디자인이다.
- 색·글꼴·간격은 Figma 값을 CSS 변수(src/styles/tokens.css)로 옮겨 사용한다. 글꼴은 Noto Serif KR(제목·본문) / Noto Sans KR(UI).
- 각 화면은 한 화면 높이로 고정되고 내용 영역만 스크롤된다. 노치 단말을 위해 상단 safe-area 여백을 둔다.

## 3.3 하단 탭 바

「책장」(/), 「오늘」(/today), 「설정」(/settings) 3개 탭. 책장·사진 올리기·설정 화면에만 표시하며 통화·리더·시트에는 표시하지 않는다.

## 3.4 서버 호출 공통 규칙

- 모든 서버 호출에는 로딩 상태와 실패 상태를 둔다.
- 실패 시 “무엇이 저장되어 있는지”와 「다시 시도」 버튼을 보여 준다.
- 기다리는 작업은 GET /jobs/:jobId를 2초마다 확인하고 완료되면 자동으로 다음 화면으로 간다(6.6장).
- 서버 데이터는 TanStack Query로, 통화 화면 상태는 useReducer로 관리한다.

## 3.5 mock 모드

VITE_USE_MOCK=true이면 src/api/mock.ts가 실제 서버와 같은 모양의 가짜 응답을 돌려준다. 호출마다 0.5~2초 지연을 넣고, 기다리는 화면은 약 5초 뒤 완료된다. 예시 데이터는 전주 3일 여행(경기전, 콩나물국밥집, 14:00–16:50 사진 없음, 골목 카페, 오목대)이다. 실제 서버 주소는 VITE_API_BASE_URL로 지정한다.

### 6.1.3 시작 시 오디오 잠금 해제

- 브라우저(특히 iOS Safari)는 사용자 조작 없이는 소리를 재생하지 못한다. 그래서 「받기」를 누르는 그 순간(같은 클릭 처리 안)에 ① 오디오 요소를 만들어 무음 파일을 재생하고 ② AudioContext를 resume한다.
- 이후 모든 질문 음성은 이 같은 오디오 요소에 주소(src)만 바꿔 재생한다. 질문마다 새 요소를 만들지 않는다.
- 마이크 권한 요청과 interview/start 호출은 이 잠금 해제 뒤에 이어서 한다(권한 창 때문에 클릭 처리가 끊겨도 오디오는 이미 풀려 있음).

### 6.1.4 병행 상황 처리

- 끊기 시트가 열린 사이에 직전 답변의 응답이 도착하면 바로 재생하지 않고 보류한다. 시트를 「계속 이야기하기」로 닫을 때 보류된 다음 질문을 재생하고, 보류된 것이 “마지막 응답(next=null)”이면 마무리로 간다. 「저장하고 마치기」를 누르면 보류분과 관계없이 마무리로 간다.
- thinking 중 시트를 열었다 닫으면(응답 대기 중) 아무것도 재생하지 않는다. 응답이 도착하는 순간 시트가 닫혀 있으면 곧바로 다음 질문을 재생한다.
- 전송 실패 상태에서 시트를 닫으면 질문을 다시 재생하지 않는다(오류 카드 유지).
- 화면을 벗어나면(unmount) 녹음·오디오·마이크 스트림·AudioContext·타이머를 모두 정리한다.

### 6.1.5 질문 · 마무리 데이터

- 수치: 통화 시간은 1초 단위(mm:ss), 질문 음성 재생이 막히면 1.2초 뒤 진행, 무음 감지 100ms 주기·2초, 한 답변 최대 55초, 말소리 임계값 RMS 0.03.
- 질문은 { index, total, text, audioUrl, sceneRef }. 마지막 질문 여부는 index = total로 판단하며 상태 문구가 “마지막 질문이에요”로 바뀐다.
- sceneRef가 있으면 「질문 근거 장면」 카드를 보여 준다. 없으면(마지막 질문 등) 카드 영역을 숨긴다.
- 마무리의 통계: 질문 n개 = 답한 질문 수(건너뛴 질문·빈 답변 제외), 시간 = 통화 시간, 장면 k개 = 오늘의 장면 수. 오늘의 순간 칩은 마지막 응답의 moments이며 중간에 마치면 비어 있어 칩 영역이 보이지 않는다.

## 6.2 무음 2초 · 55초 자동 종료 규칙

목표: 사용자가 말을 마치면 버튼 없이 자연스럽게 다음 질문으로 넘어가되, 말하기 전 침묵이나 짧은 숨 고르기로 잘못 끊기지 않게 하고, 음성 인식 API 제한(60초)을 넘기지 않는다.

### 6.2.1 말소리 · 무음 판정 알고리즘

| 단계 | 내용 |
|---|---|
| ① 준비 | 마이크 스트림에서 분석기(AnalyserNode, fftSize 1024)를 만든다. 녹음(MediaRecorder)을 250ms 단위 조각으로 시작한다. |
| ② 샘플링 | 100ms마다 시간 영역 파형(0~255, 무음=128)을 읽는다. |
| ③ 크기 계산 | RMS = √( 평균( ((값 − 128) / 128)² ) ). 0(완전 무음) ~ 1(최대). |
| ④ 말소리 판정 | RMS > 0.03이면 “말소리”. 처음 말소리가 잡히면 “말소리 감지됨” 표시를 켜고(파형이 움직이기 시작, 힌트 문구가 “말이 끝나면 자동으로 넘어가요”로 바뀜) 무음 누적 시간을 0으로 되돌린다. |
| ⑤ 무음 누적 | 말소리가 한 번이라도 감지된 뒤에만, RMS ≤ 0.03인 샘플마다 무음 누적 시간에 100ms를 더한다. 말소리가 다시 잡히면 0으로 되돌린다. |
| ⑥ 자동 종료 | 무음 누적 시간이 2000ms 이상이 되면 녹음을 종료하고 전송한다. |

### 6.2.2 종료 조건 (먼저 만족하는 것 하나)

| 순서 무관 조건 | 동작 | 비고 |
|---|---|---|
| 무음 2초(말소리 감지 이후) | 자동 종료 → 전송 | 정상 흐름 |
| 「다 말했어요」 탭 | 즉시 종료 → 전송 | 말소리 감지 여부와 무관 |
| 녹음 시작 후 55초 경과 | 자동 종료 → 전송 | 말소리 감지 여부와 무관. 이 시간은 한 답변 전체(말 시작 전 침묵 포함)에 적용 |
| 「다시 듣기」/「이 질문 건너뛰기」/ 끊기 | 녹음 폐기(전송 안 함) | 타이머 모두 해제 |

### 6.2.3 중복 종료 방지 · 정리

- 종료가 시작되면 먼저 모든 타이머(무음 감지, 55초, 자동 진행)를 해제한다. 이후 같은 녹음에 대해 다른 종료 조건이 겹쳐도 한 번만 전송된다(녹음 상태가 이미 inactive면 무시).
- 녹음 종료 이벤트에서 조각을 합쳐 하나의 파일(Blob)로 만든 뒤 전송한다. 형식은 지원되는 audio/webm(opus) → audio/webm → audio/mp4 순.
- 폐기(다시 듣기·건너뛰기·끊기)는 종료 이벤트를 연결 해제한 뒤 녹음을 멈춘다. 따라서 폐기된 녹음은 전송되지 않는다.

### 6.2.4 엣지 케이스

| 상황 | 동작 | 이유 · 비고 |
|---|---|---|
| 질문이 끝났는데 사용자가 말을 시작하지 않음 | 무음 누적이 시작되지 않으므로 자동 종료되지 않는다. 힌트 문구가 “말씀이 들리면 자동으로 이어져요. 소리가 안 들리면 마이크를 확인해 주세요”로 유지되고, 최대 55초 또는 「다 말했어요」로 끝난다. | 말하기 전 침묵으로 답이 잘리는 것을 막기 위함. 아무 말 없이 55초를 보내면 빈 답변이 전송될 수 있음 |
| 말 중간에 2초 이상 생각하며 멈춤 | 그 시점에 자동 종료된다. | 규칙 그대로(2초). 필요하면 SILENCE_MS 상수로 조정 |
| 주변 소음이 커서 RMS가 항상 0.03을 넘음 | 말소리가 끝나도 무음이 쌓이지 않아 자동 종료되지 않는다. 「다 말했어요」 또는 55초로 끝난다. | 임계값 고정(0.03). 소음 환경 보정은 후속 과제 |
| 아주 작은 목소리(RMS ≤ 0.03) | 말소리로 인식되지 않아 자동 종료가 동작하지 않는다. | 마이크 확인 안내 문구가 유지됨 |

## 6.3 끊기 확인 시트

### 6.3.1 진입과 부수 효과

- 끊기(빨간 전화) 버튼은 바로 통화를 종료하지 않는다. 항상 확인 시트를 먼저 연다.
- 시트가 열리는 즉시: ① 재생 중이던 질문 음성을 일시정지 ② 진행 중이던 녹음을 폐기(전송하지 않음) ③ 무음·55초 타이머 해제. 통화 시간은 계속 흐른다.
- 시트 뒤의 통화 화면은 어둡게(rgba(16,24,32,0.44)) 덮이고, 시트는 화면 하단에서 올라온다(높이 410px).

### 6.3.2 문구 규칙

“지금까지 답한 질문 {n}개는 저장돼요. 남은 질문 {m}개는 건너뛰어요.” — n = 답한 질문 수(건너뛴 질문·빈 답변은 제외), m = 전체 질문 수 − n(0 미만이면 0).

### 6.3.3 선택지별 동작

| 선택지 | 동작 | 결과 상태 | 비고 |
|---|---|---|---|
| 여기까지 저장하고 마치기 (주 버튼) | 보류 중인 응답과 관계없이 모든 자원을 해제하고 마무리 화면으로 간다. 서버에 인터뷰 종료(SAVE_EXIT)를 알린다(응답을 기다리지 않음). 오늘의 순간 칩은 마지막 응답에서만 받으므로 중간 종료에서는 비어 있다. | wrapUp | 이어서 「오늘의 챕터 만들기」로 챕터를 만들 수 있다 |
| 계속 이야기하기 (외곽선) | 시트를 닫고 보류분이 있으면 그것을 처리(다음 질문 재생/마무리), 없으면 현재 질문을 처음부터 다시 재생한다. 전송 실패 중이거나 응답 대기(thinking) 중이면 재생하지 않는다. | aiSpeaking / thinking / wrapUp | 시트 바깥(어두운 영역) 탭도 같은 동작 |
| 저장하지 않고 나가기 (회색 텍스트) | 통화를 종료하고 책장으로 이동한다. 서버에 DISCARD를 알려 이번 인터뷰의 음성·전사를 삭제하게 한다(응답을 기다리지 않는 best-effort). | (이탈) | 마무리(챕터 만들기)는 하지 않음. 종료 호출 없이 끊긴 인터뷰는 다음 「받기」에서 이어 하기가 된다 |

### 6.3.4 엣지 케이스

- 답한 질문이 0개일 때도 시트와 「저장하고 마치기」가 동작한다(“질문 0개”).
- 시트가 열린 상태에서 질문 응답이 도착하면 보류(6.1.4). 보류 후 「저장하고 마치기」를 누르면 그 응답은 무시되고 마무리로 간다. 이때 마지막 응답의 오늘의 순간 칩이 있으면 마무리에 표시된다.
- 시트를 연 상태에서 브라우저 뒤로 가기를 누르면 통화 화면 자체를 벗어난다(자원 정리). 시트는 별도 history 항목이 아니다.

## 6.4 마이크 사용

- 권한은 「받기」를 누르는 순간에만 요청한다(미리 요청하지 않음). 요청: getUserMedia({ audio: { echoCancellation: true, noiseSuppression: true } }) — 질문 음성이 마이크로 되먹임되지 않도록 에코 제거를 켠다.
- 한 번 얻은 스트림은 통화 내내 재사용하고, 마무리·이탈 시 모든 트랙을 중지한다.
- 마이크는 HTTPS 또는 localhost에서만 동작한다. LAN 주소(http://192.168.x.x)로 폰에서 접속하면 쓸 수 없으므로 폰 시연은 HTTPS 배포나 터널이 필요하다.
- iOS Safari는 오디오 재생 정책이 엄격해 6.1.3의 잠금 해제가 필수이며 실기기 검증이 필요하다.
- 통화 중 권한 철회·장치 분리는 처리하지 않는다(알려진 제한).

## 6.5 문체 바꾸기 시트

문체 코드는 ESSAY / EMOTIONAL / FAIRYTALE이며 소설(NOVEL)은 화면에 없어 제외한다(03 설계서 C-05).

### 6.5.3 상태와 동작

| 상태 | 조건 | 화면 | 가능한 동작 |
|---|---|---|---|
| 대기(기본) | 시트 열림 | 라디오 3개(1개 선택), 하단 「이 문체로 다시 쓰기」 | 선택 변경, 다시 쓰기, 닫기(바깥 탭) |

| 작업 진행 | jobId 수신 후 2초마다 확인 | 위와 같음 | 대기(닫을 수 없음) |
| 완료 | 작업 done | 시트 닫힘, 토스트 | - |
| 실패 | 요청 실패 / 작업 failed / 상태 조회 오류 | 붉은 문구 “다시 쓰지 못했어요. 지금 책은 그대로 있어요.”, 버튼 「다시 시도」 | 다시 시도, 선택 변경, 닫기 |

### 6.5.4 규칙

- 요청 중·작업 진행 중에는 라디오 선택과 시트 닫기(바깥 탭 포함)를 모두 막아 중복 요청과 상태 불일치를 방지한다.
- 시트를 다시 열면 상태가 초기화된다(선택 = 진입 경로의 초기 선택, 실패 문구 제거, 작업 번호 비움).
- 실패해도 기존 본문은 바뀌지 않는다. 서버는 새 문체 생성이 끝난 뒤에만 책 본문을 교체해야 한다(원자성).
- 범위: 문체 변경은 책 전체에 적용되는 작업이다(요청에 챕터 번호 없음). 리더는 완료 후 현재 챕터만 다시 불러오므로 나머지 챕터는 다음에 열 때 새 문체로 보인다.
- 현재 시연(mock)에서는 문체 상태가 앱 메모리에만 있어 새로고침하면 에세이로 돌아간다. 서버 연동 시 책 단위(tb_trip.writing_style)로 저장된다(03 설계서).

멱등성(04 4장, 03 설계서 10장): 화면 재시도·새로고침으로 analyze / chapter / finish / restyle이 같은 입력으로 다시 호출될 수 있다. 서버는 중복 작업·중복 책을 만들지 않아야 하고, 작업이 실패해도 기존 데이터(사진·답변·본문)는 보존해야 한다.

# 8. 비기능 요구사항

- 지원 환경: 아이폰 Safari, 안드로이드 Chrome. 폭 360~430px에서 가로 스크롤이 없어야 한다.
- 모든 글자와 버튼은 실제 요소로 만든다(화면 전체를 이미지로 넣지 않는다). 아이콘 버튼에는 aria-label을 둔다.
- 움직임 줄이기(prefers-reduced-motion) 설정에서는 파형·점·종이 조각 애니메이션을 끈다.
- 마이크 사용은 HTTPS(또는 localhost)가 필요하다. 사진 업로드는 서버가 준 주소로 브라우저가 직접 올리며, API 키·비밀 값을 프론트엔드에 두지 않는다.

# 9. 범위 · 제한 사항

## 9.1 디자인에 없어 추가한 화면

Figma에 없던 상태·화면은 같은 테마(색, 서체, 모서리, 그림자)로 직접 구성했다. 디자인 확정 시 교체 대상이다.

- 사진 올리기: 선택 전(빈 상태), 업로드 중 문구, 일부 실패
- 통화: 시작 실패 안내, 답변 전송 실패 카드
- 새 여행: 날짜 선택 시트
- 책 엮는 중 실패, 모든 로딩·오류 화면
- 책 상세: PDF 내보내기 시트
- 리더: 글자 크기(Aa) 시트, 책갈피 토스트
- 설정: 인터뷰어 목소리 선택, 데이터 삭제 확인, 서비스 정보 시트

## 9.2 알려진 제한

- 실제 서버 연동은 검증하지 않았다(mock으로만 전체 흐름 확인). 서버가 준비되면 환경 변수만 바꿔 연결한다.
- 실기기(아이폰 Safari, 안드로이드 Chrome)에서의 실제 녹음·무음 감지·55초 제한은 별도 확인이 필요하다.
- 무음 감지 임계값(0.03)은 고정이며 소음 환경 보정이 없다. 말하기 전 침묵이 55초 이어지면 빈 답변이 전송될 수 있다.
- 통화 중 마이크 권한 철회·장치 분리는 처리하지 않는다.
- mock의 질문 음성은 무음 파일이다. mock 리더의 「그때 내 목소리」는 브라우저 음성 합성으로 대신 읽는다.
- PDF 내보내기는 인쇄용 페이지 + 브라우저 「PDF로 저장」으로 만든다. 서버 API·작업은 없다(03 설계서 C-06).
- 책갈피는 서버에 저장하지 않는다. 문체 선택은 mock에서는 메모리에만 있다.
- 장면이 0개인 경우의 전용 화면은 없다(서버가 최소 1개를 보장한다).
- 인터뷰를 시작한 일차에는 서버가 사진 추가를 막는다(409 INTERVIEW_STARTED). 이때 사진 올리기 화면은 일반 실패 문구(“업로드 주소를 받지 못했어요…”)를 보여 주며 전용 안내 문구는 정하지 않았다. 「저장하지 않고 나가기」(DISCARD)를 하면 다시 올릴 수 있다.
- 책 엮기가 실패했을 때 책장 진행 블록에는 실패 표시가 없다(「오늘」 탭 → 책 엮는 중 화면에서 확인).
- 쿠키를 잃으면(삭제·다른 브라우저·시크릿 창) 기존 책장을 복구할 수 없다. 의도된 정책이다(03 설계서 C-03). 쿠키 차단 브라우저를 위한 안내 문구는 정하지 않았다.
- 문체는 에세이·감성·동화 3종이다(소설 제외).
- 로그인·회원가입, PC 화면, 다크 모드 전환은 범위에 없다.
